## 2. 全站維護決策

使用者確認：**全站維護是獨立的全站維護控制，不計入七個維護範圍。**

技術設計採 `maintenance_events.is_global = true` 表示全站事件，不建立第八個 scope code，也不將全站當成七個 scope 的其中一項。

- 全站事件與任一局部事件時間重疊時，排程視為衝突。
- 全站事件不可同時選取局部 scope。
- 局部事件可同時選取一個或多個已確認的七個 scope。
- 全站事件彼此時間重疊亦視為衝突。

## 3. 管理員後台存取決策

使用者確認：**全站維護時管理員仍可登入管理後台。**

實作要求：
- 一般訪客及一般使用者依全站／所屬範圍看到維護提示或受限操作。
- 管理員可進入後台查看、建立、修改或解除維護事件。
- 管理員仍必須經過 JWT 驗證與伺服器端 admin role 檢查；maintenance bypass 只控制維護畫面／維護限制，不是資料權限後門。
- 若認證服務本身不可用，管理員登入仍可能失效；需另行設計緊急復原方案。

## 4. 前台範圍對應（暫定映射）

以下以現有導覽及後台模組作初步映射，不視為完整服務依賴清單：

- `site_core`：首頁、網站內容、快速連結。
- `announcements_info`：最新消息、公告管理、行事曆、AI 公告。
- `events_competitions`：活動／比賽、達人榜、報名、簽到。
- `video_content`：影音頻道。
- `membership_growth`：訪客帳號、個人中心、會員成長、獎勵、優惠券、通知。
- `store_support`：商品、訂單、客服中心。
- `downloads_app`：檔案下載、App 更新、App 設定。

共用登入、profiles、通知推送、搜尋及共用 API 是否跟隨特定 scope 停用，尚未決定；不能僅憑頁面歸類就停用共用服務。

## 5. 維護狀態呈現原則

- 維護是否生效以伺服器／資料庫時間判斷。
- 前台狀態 API 只回傳公開提示必要資料，不回傳內部備註或 audit。
- 管理員維護頁面不受全站維護畫面阻擋，但所有管理 API 仍執行權限驗證。
- 局部維護時，未受影響的範圍原則上維持可用；若依賴被維護的共用服務，需另訂降級行為。
- 是否只顯示警示、唯讀或全面封鎖，依各 scope 的產品需求逐項決定。
